# 债台账（技术债与问题清单）

> **这份文件必须保持最新。** 它本身过期过一次（两项已做完还写着"待做"），
> 而那一次直接导致"还债"排不出优先级。
>
> 每次改完代码，**先扫一遍这张表**；每还清一项，**当次就删掉/标记**。
>
> 更新：2026-10-30

## 严重度定义

| 级别 | 含义 | 处理时机 |
| --- | --- | --- |
| **P0** | **陈述不实 / 会误导**。别人（面试官、同事）一看就能发现"文档说的和实际不一样" | **接口/部署之前必须清** |
| **P1** | 影响可维护性、可验证性。不修不会立刻出事，但会拖慢后续每一步 | 接口之前清 |
| **P2** | 有明确触发条件（接真实数据 / 部署 / 重构到某处）。**到条件时再做，现在做是浪费** | 触发时 |
