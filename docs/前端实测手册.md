# 链路 A：看数据（3 分钟，先把"它有没有通"确认掉）

## A1 · 登录

```text
做什么：打开 http://localhost:5173
预期：  跳到 /login，左边深色品牌区，右边表单

```

**这一条不过 = 后面全白测**（后端没起 / 代理没通 / 账号不对 ✅）

## A2 · 今日工作台（页 1）

```text
看这 4 样：
① **AI 日报卡**（蓝色渐变底）→ 应该有 3~5 条中文，比如「📊 今天 123 个簇」
   ⚠️ 如果是「还没有生成过 AI 日报」→ 正常，跑 `hub brief` 就有了
② **P 档环形图** → P0=2 / P1=5 / P2=8 / P3=7（加起来 22）
③ **4 张 KPI 卡** → 「要我做」应该 ≥1、「等观察窗口」应该 ≥1
   ⚠️ 数字是等宽字体（切换数据时不跳 ✅）
④ **「要我做」列表** → 点一条，应该跳到提案详情 / 运维台
```

**判定**：环形的 4 块**都有**、KPI 不是全 0、点条目**能跳** → ✅

## A3 · 问题全景（页 3）

```text
看这 6 样：

⑦ 簇条数条形  → 12 条横条，最长的是「掉色严重」

⑨ 差评率趋势  → ⚠️ **可能是空的**（走空态），**这是正常的** ✅
⑩ 价格散点    → 一堆点，鼠标悬停显示「商品名 / 价格 / 差评率」
⑪ GMV Top10   → 表格，GMV 列是「¥6867.5 万」这种
点表格里的行 → 跳到提案列表
点「导出 xlsx」→ **浏览器直接下载一个 xlsx** ✅
```

**判定**：⑥⑦⑧⑩⑪ **五张有数据**、⑨ 空态**有"为什么空"的说明** → ✅

# 链路 B：处理一件真事（**最值得测的一条**，5 分钟）

> 这条走完，你就把「agent 出方案 → 采纳成提案 → 主管批准 → 执行」**全串起来了** ✅

## B1 · 让 agent 出方案（页 5）

```text
做什么：左侧菜单「处理 → Agent 任务」
做什么：下拉选一个簇（比如「掉色严重 · P0 · 123 条」）→ 点「让 agent 出方案」
看到：  ① 状态变「运行中」（每 2 秒轮询）
        ② 约 5~10 秒后变「完成」，下面出现：
           · **结论卡**：工具名 + 推荐内容 + 置信度
           · **轨迹**：4 步（查簇 → 查评价 → 查历史 → 模型判断）
           · **token**：「689 in / 57 out」这种
           · **证据**：E-CLUSTER / E-REVIEWS / E-HISTORY 编号
```

**重点看**：**第 4 步是"模型判断"，前 3 步都是工具** ✅
—— 这就是"形态③"的可见证据（**模型只判一次，不自己规划** ✅）

**如果 409**：说明这个簇已经有任务 → 页面会自动去轮询那个任务 ✅（**不是报错** ✅）

## B2 · 采纳成提案

```text
做什么：结论卡右上角点「采纳 → 生成提案」
预期：  ① 提示"已生成提案"
        ② **自动跳到提案详情页**
        ③ 再点一次采纳 → 提示"这条已经采纳过了（幂等 ✅）"
```

## B3 · 看提案详情（页 2）—— **这一页是核心**

```text
三栏都要看：
左栏「内容」
  · 为什么做这个动作（蓝色左边框那段）
  · 参数（spu_id / platform / content）
  · 底部：工具版本 / trace_id / 时间
中栏「依据」  ← **最重要的**
  · 顶部写「这个簇共 123 条评价，先看代表样本」
  · 下面是**真实评价原文**，其中「掉色」是**黄色高亮**
  · 每条带「1 星 / jd / 代表样本 / 日期」
  · 这条不通 = 我补的 `/clusters/{id}/reviews` 没生效 ✅
右栏「风险与决定」
  · 「L2 · 需要**主管批准**」
  · 历史战绩（可能显示"还没有历史"）
  · 两个按钮：批准 / 拒绝
```

## B4 · 换 supervisor 登录 → 批准

```text
做什么：右上角用户 → 登出（**这时后端会把这个 token 拉黑** ✅）
做什么：用 supervisor@hub.local / 123456 登录
做什么：回到这条提案 → 点「批准（会真执行）」
预期：  ① 成功提示
        ② 状态变「已执行」
        ③ **运维台的日志里多一条 `proposal.approve`**
```

**这一步验证的是**：`operator` 看不到批准按钮（B3 时你应该**没看到**那个按钮 ✅）、
`supervisor` 看得到、**批准后真的执行 + 写审计** ✅

## B5 · 拒绝也要测（**空原因必须被拦**）

```text
做什么：（用 supervisor）打开另一条提案 → 点「拒绝」
预期：  ① 抽屉打开，输入框空时「确认拒绝」**是灰的**
        ② 填一句原因 → 按钮变亮 → 点确认 → 状态变「已拒绝」
```

# 链路 C：沉淀与复盘（3 分钟）

## C1 · 知识库（页 8）—— **现在 0 条，正好测"建 + 发布"**

```text
做什么：菜单「知识库」→ 应该看到空态「还没有知识条目」
做什么：点右上角「新建条目」
  · 标题：质量问题回复口径
  · 范围：质量
  · 内容：先道歉，再解释掉色原因（面料固色工艺），最后给出补救方案
  → 点「创建（DRAFT，还不生效）」
预期：  卡片出现，标着 **DRAFT v1** + 黄色标签「**DRAFT 不生效，发布后才注入**」✅
做什么：点「发布」
预期：  变 **PUBLISHED v2** + 绿色标签「**已注入提示词**」✅
```

**这一条的关键**：**DRAFT 和 PUBLISHED 的标签不一样** ✅
—— 这就是"业务方发一条口径，AI 的行为就变"的可见证据 ✅

## C2 · 通知中心（页 7）—— **跑过 §0 的第 ③ 步才有数据**

```text
看：  ① 顶部「N 条未读 · 共 N 条」
      ② 每条左边有色标签（提案待批=黄 / 死信=红 / Agent 需人工=灰）
      ③ **未读的左边有一条蓝竖线**
做什么：点一条 → 应该跳到对应页面（提案 → 提案详情；死信 → 运维台）
预期：  跳过去 + **那条变"已读"**（蓝竖线消失）
```

## C3 · 复盘报告（页 4）—— **现在必然全是"等窗口"**

```text
看：4 张卡 → 有效 0 / 有害 0 / 不能下结论 0 / **等观察窗口 4**
   中间有一段：「现在还没有能下结论的动作」
   + 「为什么不现在就下结论？」三条理由
   ⚠️ **这就是正确状态** —— 真实干预还在观察窗口（最早 2026-11-13）✅
做什么：点「重新复盘」→ 提示「复盘完成：0 组有结论，4 组跳过」
做什么：点「导出 xlsx」→ 下载 retro.xlsx
```

**如果有人问"你复盘有效果吗"，这一页就是答案**：**没有，因为窗口没到，我不编** ✅

## C4 · 运维台（页 6）—— **上传 + 危险操作**

```text
看：  ① 系统健康 → 绿色「正常」
      ② 最近门禁 → 「硬门禁 19/19」
上传：
  · 平台选 **京东**、类型选 **销售**
  · 点「选择 xlsx 上传」→ 选 `data\mock\jd_sales_202610.xlsx`
  · 预期：绿色「已导过」或「入库 2250 条」
**故意传错**：
  · 平台改选 **淘宝**，再传同一个 jd 文件
  · 预期：黄色「入库 0 条」+ **红字 warning**「最常见的原因是 platform 传错」✅
危险操作：
  · 点「触发全链」→ **弹二次确认** → 取消（别真跑，710 秒 ✅）
  · 重放死信：前缀随便填 4 位 → 点重放 → **弹红色确认** → 取消
日志：下面的表格 → 应该能看到你刚才**批准/上传**的记录 ✅
```

# 三个阶段性的"判定标准"

```text
【及格】链路 A 全过 + 链路 B 的 B1/B3 能看到真实评价原文
   → 说明「前后端真的通了，而且核心卖点成立」

【良好】链路 B 全部（含批准 → 日志多一条）+ 链路 C 的 C1（DRAFT→PUBLISHED）
   → 说明「写接口 + 审计 + 知识注入都通了」

【优秀】C4 的"故意传错"能看到红字 warning + C3 的复盘页能解释"为什么没结论"
   → 说明「异常路径也考虑到了，不是只会成功」
```
