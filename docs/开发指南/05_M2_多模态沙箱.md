## 1. 目标

把买家秀图片"读成结构化标签"（破损/色差/严重度），然后**物理销毁原图**。核心诉求是合规：图片版权不属于商家，只做内部分析，不落库、不二次开发、不对外展示。

**判断标准**：`make sandbox` 处理一批带图评价，能证明两件事——① 原图 100% 销毁（`shred_ok=100%`）；② 系统里只剩哈希和标签，没有一张原图。

> 这一篇是**合规红线**，不是普通功能。面试讲它的时候，重点不是"我调了 Vision"，而是"我怎么证明原图没了"。

## 4. 实现思路

### 4.1 下载与 SSRF 防护（sandbox.py）

**为什么有 SSRF 风险**：图片 URL 来自用户评价，如果直接 `requests.get(url)`，攻击者可以放 `http://127.0.0.1:6379/` 这类内网地址，让服务器去访问内部服务。

**四道防护**：

| 步骤 | 规则 |
| --- | --- |
| 协议白名单 | 只允许 `http/https`，拒绝 `file://`、`gopher://` |
| 域名解析校验 | 解析出 IP 必须是公网（拒绝 `127.x`、`10.x`、`192.168.x`、`169.254.x` 等） |
| DNS 二次校验 | 拿到 IP 后**用该 IP 重连**并校验证书 Host，防 DNS rebinding |
| 重定向限制 | 最多 3 次重定向，且每次都要重新过上述校验 |

**下载**：目标目录 `/dev/shm/hub-sandbox/{run_id}/`（tmpfs，内存盘，不落物理磁盘）。下载超时 10s。

### 4.2 体积/格式校验 + 剥 EXIF

```text
体积：≤ 5MB（Content-Length 预检，超限直接拒，不下载完整字节）
格式：jpeg/png/webp（Pillow verify 通过）
重编码：Pillow 打开 → 转 RGB → 重新保存
       （这一步同时剥离 EXIF/GPS 定位信息，防买家位置泄露）
```

### 4.3 pHash 去重复用（phash.py）

**为什么**：同一张破损图可能被多人转发，重复调 Vision 是浪费。用感知哈希去重：

```text
pHash 计算 → 与库中已有 hash 比汉明距离 → ≤6 判为"同图"
→ 命中：直接复用已有 VisionTags，不再调 Vision
→ 未命中：调 Vision，结果与 phash 一起入库
```

### 4.4 Vision 抽取（vision_client.py）

```python
class VisionTags(BaseModel):
    is_product_image: bool
    defect_type: Literal["none", "破损", "污渍", "色差", "开线", "错发", "尺码不符", "其他"]
    severity: int = Field(ge=0, le=3)          # 0 无 3 严重
    color_deviation: float = Field(ge=0, le=1)
    confidence: float = Field(ge=0, le=1)
```

**要点**：

1. 输出走 Pydantic 强约束（和 M3 归因同一套结构化输出机制）；
2. `confidence < 0.5` 或 `is_product_image=False` → 只保留 `defect_type="none"` 并标 `low_confidence`，**不影响文本链路继续**；
3. **开发策略：先 mock**（返回固定标签），Vision Key 到位后再接真实现——mock 期间把"沙箱 + 销毁"这套真正需要验证的部分先跑通。

### 4.5 覆写销毁 + 审计（shredder.py + audit.py）

**为什么普通删除不够**：`os.remove()` 只是删了目录项，数据块还在磁盘上（尤其 SSD 写时复制）。所以要覆写：

```python
def secure_shred(path, passes=3):
    size = path.stat().st_size
    for _ in range(passes):
        with open(path, "wb") as f:
            f.write(os.urandom(size))
        f.flush(); os.fsync(f.fileno())   # 落盘
    path.unlink()
    return ShredResult(ok=True, bytes=size, shred_ts=now())
```

**三重保障**（设计文档 §3.2.4）：

1. **tmpfs 内存盘**：文件本就不落物理磁盘，卸载即消失；
2. **覆写删除**：`urandom` 覆写 + `fsync` + `unlink`；
3. **容器销毁**（P1）：任务结束 `docker rm -f`，整个沙箱进程空间销毁。

**审计（audit.py）**：每次处理写 `sandbox_audit` 表：`{trace_id, image_sha256, bytes, shredded_at, shred_ok}`。这是 G2 门禁"100% 销毁"的**证据**。

### 4.6 启动自检（selfcheck.py）

```python
def assert_sandbox_dir(cfg):
    mount = get_mount_point(cfg.sandbox_dir)     # 读 /proc/mounts
    if "tmpfs" not in mount.fstype:
        raise HubError("CPP-2001 SANDBOX_NOT_TMPFS")   # 拒绝启动
```

**为什么**：如果运维把 `sandbox_dir` 误配到物理盘，覆写删除就"不可证"，合规直接破功。所以启动时校验，不在 tmpfs 就拒绝启动——**用代码强制合规，而不是靠自觉**。

## 9. 常见坑

1. **覆写删除在 SSD 上不可证**：写时复制文件系统下，覆写可能写到新块、原块还在。**这正是为什么必须用 tmpfs**——别只靠 `secure_shred`，tmpfs 才是根本保障；
2. **SSRF 只查了域名没查解析后的 IP**：`http://127.0.0.1` 直接写 IP 就绕过了域名白名单，所以**必须解析后校验 IP**；
3. **DNS rebinding**：第一次解析是公网、第二次解析成内网。**用解析出的 IP 重连 + 校验证书 Host**；
4. **原图 URL 落库了**：想着"URL 不是图片，存一下方便重试"，但这等于留下二次拉取的入口。**URL 用完即弃，不落库**；
5. **审计表没写 shred 结果**：只写了"处理过"，没写"销毁成功与否"，G2 门禁就没法证明。**shred_ok 必须落库**；
6. **Vision 失败拖垮整批**：单张图超时 30s，1000 张就是 8 小时。**并发 + 超时 + 失败降级为纯文本，不阻塞**。
