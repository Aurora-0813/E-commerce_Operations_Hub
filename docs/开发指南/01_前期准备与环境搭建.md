## 1. 目标

把"能开始写代码"的前置条件全部备齐。做完这篇，你手上要有：可用的 Python 环境、装好的依赖、能跑的 Docker、LLM Key、真实数据文件、初始化好的 git 仓库和目录骨架。

**判断标准**：下一篇（02）可以无阻碍地开始写第一行代码。

## 2. 需求对齐（动手前最后确认一次边界）

对照立项书，本项目 = 跨平台电商运营决策中枢，M1–M9 九个模块，主线四段闭环：

```text
数据降噪(M1) + 多模态(M2) → 归因分析(M3/M4) → 网关执行(M5/M6) → 调度复盘(M7/M9)
```

**三条边界，写下来贴在显眼处**：

1. 只做后端，前端页面不碰；
2. 输入只有"导出文件"（淘宝/京东 CSV/XLSX），没有平台 API；
3. 图片只做内部分析，阅后即焚，不落库、不二次开发、不对外展示。

## 3. 技术选型确认（照设计文档，不再纠结）

| 领域 | 选型 | 一句话理由 |
| --- | --- | --- |
| 语言 | Python 3.11 | 数据 + LLM 生态 |
| 契约/校验 | Pydantic v2 | 与 LLM 结构化输出同源 |
| API | FastAPI | 自动 OpenAPI |
| 编排 | LangGraph + Checkpointer | 立项书指定，多步状态机 |
| 数据 | pandas + pyarrow | parquet 列式 |
| 小模型 | scikit-learn + jieba | CPU 可训可解释 |
| 存储 | SQLAlchemy + SQLite（dev）/ PG15（生产） | 开发零运维 |
| 队列 | Redis Stream（dev 可 fakeredis） | 消费组/DLQ |
| LLM | OpenAI 兼容接口 | 可换供应商、可 mock |
| 图片 | Pillow + imagehash | pHash 去重 |

> 明确**不装**：LangChain 全家桶（只用 LangGraph）、pgvector（Case RAG 向量用 numpy/FLOAT8[]）。

## 9. 常见坑（这一阶段最容易翻车）

1. **Python 版本**：系统默认 3.9/3.10，务必用 3.11（`3.11` 的 `StrEnum`/`|` 类型注解依赖它）；
2. **Windows 编码**：导出文件是 GBK，pandas 直接 `read_excel` 可能乱码——下一篇适配器会专门处理，但数据文件本身别用记事本"另存"破坏编码；
3. **Key 泄露**：`.env` 没加 gitignore，commit 了再删也还在历史里，只能换 Key；
4. **Docker 没装/没起**：M2/M7 依赖，但**别卡在 Docker 上**——02 的 skeleton 不依赖 Docker，可以先往下走；
5. **数据一直拿不到**：这是全项目最大的风险，**第一天就催**，别等写到适配器才要。
