## 4. 实现思路

### 4.1 多阶段 Dockerfile

```dockerfile
# 阶段1：builder —— 装依赖
FROM python:3.11-slim AS builder
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 阶段2：runtime —— 瘦身、非 root
FROM python:3.11-slim
COPY --from=builder /usr/local/lib/python3.11/site-packages ...
COPY hub/ /app/hub
RUN useradd -m appuser && chown -R appuser /app
USER appuser
CMD ["uvicorn", "hub.app:create_app", "--factory"]
```

**要点**：多阶段（builder 装依赖、runtime 瘦身）+ 非 root 用户 + 固定基础镜像 tag（不用 `latest`）。

### 4.2 docker compose 编排

```yaml
services:
  nginx:    {image: nginx:1.27, volumes: [./deploy/nginx.conf, ./web/dist]}
  api:      {build: ., command: uvicorn hub.app:create_app --factory}
  worker:   {build: ., command: python -m hub.scheduler.worker}
  worker-track: {build: ., command: python -m hub.scheduler.worker --role track}
  postgres: {image: postgres:15, volumes: [pgdata]}
  redis:    {image: redis:7, command: ["redis-server", "--appendonly", "yes"]}
```

**生产要求**：Postgres 主备 + 每日全量备份 + WAL 归档（RPO 15min）；Redis 开 AOF；api/worker 各自水平扩展。

### 4.3 数据库迁移

```bash
alembic revision --autogenerate -m "add xxx"
alembic upgrade head
```

**铁律**：迁移只做**向前兼容**变更（加列、加表），**不 drop 列**（drop 用"弃用→过渡期→删除"三步走）。回滚靠"兼容旧版本代码"，不靠"回滚迁移"。

### 4.4 配置与密钥管理

| 项 | 设计 |
| --- | --- |
| 密钥 | 只从环境变量 / 密钥管理服务取，**禁止落盘、禁止入仓** |
| 环境隔离 | dev / staging / prod 三套 `config/{env}.yaml` |
| 敏感开关 | `raw_export_enabled=false`、`allow_model_training=false` 为合规硬开关，启动自检校验 |
| CI 扫描 | 提交时扫 `AKIA/ghp_` 等密钥特征，命中即阻断 |

### 4.5 监控告警（关键指标）

| 告警 | 阈值 | 处置 |
| --- | --- | --- |
| DLQ 增长 | 5min ≥5 条 | 检查 + 重放 |
| 结构化合规率下降 | <98%（1h） | 查 prompt/模型版本，必要时回滚 |
| 降噪率异常 | 低于基线 3σ | 疑似模型漂移或攻击 |
| 成本超预算 | 单 run 超 ¥50 | 检查级联命中率 |
| **沙箱销毁失败** | 任一 `shred_ok=false` | **立即人工清理 + 合规上报**（最高优先级） |
| 队列积压 | XLEN >1000 持续 5min | 扩容 worker |

### 4.6 发布流程

```text
构建(CI 全绿) → 迁移(向前兼容) → 金丝雀 5% 观察 30min → 分批 25% 全量
               → 指标异常 → 镜像回滚 + 特性开关关闭
```

**回滚三件套**：上一版本镜像、向前兼容的迁移、特性开关。**不要依赖"回滚数据库迁移"**（那是危险操作）。

### 4.7 数据安全与留存

| 数据 | 留存 | 说明 |
| --- | --- | --- |
| 原图 | 0 天 | 阅后即焚 |
| 评价文本 | 180 天 | 到期清理 |
| Trace | 90 天 | 分区裁剪 |
| 审计日志 | 365 天 | 合规要求，不可删 |
| 报表文件 | 7 天 | 对象存储生命周期 |

## 6. 验收（上线准入 DoD，全项目最终门）

```bash
docker compose up -d && docker compose ps      # 全部 healthy
make demo                                       # 容器内跑通全链
```

**七条最终验收**：

1. G1–G5 全部通过并归档证据；
2. 30 条扰动 + 12 条闭环用例，硬门禁 100%；
3. 核心模块单测覆盖率 ≥ 85%，网关分支覆盖 100%；
4. 压测：5k 条评价 P95 Run ≤ 8min，无内存泄漏；
5. 合规签字：G2 销毁报告 + 导出接口审计；
6. 回滚演练：镜像回滚 + 迁移兼容验证通过；
7. `make demo` 在干净环境（新机器）从零跑通。

## 7. 常见坑

1. **密钥进了镜像**：`COPY .env /app` 把 Key 打进镜像层，删了也还在历史里。**密钥只走运行时注入**；
2. **回滚靠 drop 列**：迁移回滚是危险操作，正确姿势是"向前兼容迁移 + 旧镜像回滚"；
3. **没有非 root 运行**：容器用 root 跑，被攻破就是提权。**USER appuser**；
4. **告警没有优先级**：沙箱销毁失败和日志噪音混在一起，真出事没人看。**合规告警最高优先级**；
5. **不练回滚**：回滚脚本写了但没演练过，真出事手忙脚乱。**上线前必须演练一次**；
6. **"本机能跑"= 部署完成**：本机有各种缓存/残留，新环境跑不起来才是真问题。**验收第 7 条要求干净环境跑通**。
