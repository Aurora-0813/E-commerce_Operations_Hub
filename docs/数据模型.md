## 2. 主链路（**看这 8 张就懂整个系统**）

```text
ingest_batch（一次导入）
   └─ record（一条评价，21 列）──┬─ review_topic（分类结果）
                                 └─ record_image（买家秀）
   ↓ cluster_member（簇成员，4 列：cluster_id + record_id + is_representative）
issue_cluster（问题簇，13 列：label / review_count / priority_tier / spu_ids / business_domain）
   ↓
action_proposal（提案，13 列：tool_name / args / risk_level / evidence_refs / rationale / topic / status）
   ↓ tool_execution（执行审计，14 列）
   ↓ hitl_task（待批，9 列）
   ↓ action_outcome（复盘，17 列：effect / conclusion / reason_code / observe_end）
   ↓（回写）
experience_stat（按 (topic, tool) 的战绩）
case_entry（案例，13 列）
```

**加上 agent 这条支线**：

```text
agent_run（15 列：cluster_id / trace_id / steps JSONB / evidence JSONB / result JSONB / proposal_id）
   ↓（采纳后回填）
action_proposal
```

## 3. **有故事的字段**（改之前必看 —— 这 10 条都是踩出来的）

| # | 表.字段 | 真相 | 踩过的坑 |
| --- | --- | --- | --- |
| 1 | `issue_cluster.business_domain` | = **品类**（女装/男装），**不是问题类型** | 问题类型要从 `cluster_member → review_topic` 取**众数**；我曾准备把它改成 topic ✅ ✗ |
| 2 | `tool_execution.proposal_id` | **可空** | MCP 等外部调用没有提案 → 撞 `NOT NULL` |
| 3 | `notification` 的 `uq_notification_idem` | `(event_type, resource_id, channel, recipient)` —— **幂等由 DB 保证** | 我的 `emit()` 只查"10 分钟内的 PENDING"，已 SENT 的查不到 → 撞约束 |
| 4 | `pipeline_run` 的 `uq_pipeline_run_active` | `UNIQUE(kind) WHERE 状态活跃` → **同 kind 只能一条** | `kind="handle"` 会拒掉第二个 agent 任务 → 改成 `handle:<簇id前8位>` |
| 5 | `agent_run` 的部分唯一索引 | 同簇只允许一个未完成任务 | 重复提交 → 撞 IntegrityError（现在接住返回已有 id ✅） |
| 6 | `case_entry.case_id` | **UUID 主键**（不是字符串） | 用 `"case-test-a"` → `操作符不存在: uuid ~~ uuid` |
| 7 | `sales_daily.conversion` | **全是 NULL**（从没被填过） | 读它会得 0.0 → 看起来像"转化率 0%"这类假数据 → **用 `units / uv` 算** |
| 8 | `action_outcome.effect` | **JSONB**（不是数字） | `float(dict)` → TypeError |
| 9 | `action_outcome.observe_end` | **DATE**（不是 datetime） | 和 `datetime.now()` 比 → TypeError |
| 10 | `record.review_time` | 评价的**真实历史时间** | 我曾以为"簇成员是快照所以没有历史" ✅ ✗ → 周趋势能按它算 |

## 4. 状态机（三个"有状态"的表）

### 4.1 `action_proposal.status`

```text
PROPOSED → PENDING_APPROVAL → APPROVED → EXECUTED
    ↓            ↓                ↓
  SKIPPED     REJECTED         REJECTED
CHECK 约束：status IN ('PROPOSED','PENDING_APPROVAL','APPROVED','REJECTED','EXECUTED','SKIPPED')
```

### 4.2 `hitl_task.status`

```text
PENDING → APPROVED / REJECTED / EXPIRED
```

### 4.3 `pipeline_run.status`

```text
QUEUED → RUNNING → DONE / DEGRADED / FAILED → DEAD（进死信，需人工 replay）
CHECK 约束：status IN ('QUEUED','RUNNING','DONE','DEGRADED','FAILED','DEAD')
```

### 4.4 `action_outcome.status`

```text
WAITING（等观察窗口，最早 2026-11-13）→ CONCLUDED（有结论）
```

## 5. 唯一约束（**这些是"设计意图"，不是巧合**）

| 约束 | 保的是什么 |
| --- | --- |
| `app_user (tenant_id, email)` | 同租户邮箱唯一 |
| `notification (event_type, resource_id, channel, recipient)` | **通知幂等**（同事件只发一次） |
| `pipeline_run UNIQUE(kind) WHERE 活跃` | **同 kind 只能一条**（防两条全链同时写同一批数据） |
| `agent_run UNIQUE(cluster_id) WHERE 活跃` | 同簇只允许一个未完成任务 |
| `idempotency_record.key` | 工具调用的幂等键（写工具用） |

## 6. Redis Key（队列侧，不在 PG 里）

| Key | 用途 |
| --- | --- |
| `hub:stream:runs` | 队列 Stream（`hub queue` 能看积压） |
| `hub:queue:group` | 消费者组 |
| `hub:gpu:lock` | GPU 锁（`SET NX EX`，worker 崩了会自动释放） |
| `hub:jwt:revoked:<jti>` | **JWT 黑名单**（登出即作废，TTL = 剩余有效期） |
| `hub:ratelimit:*` | 网关频控（burst） |
