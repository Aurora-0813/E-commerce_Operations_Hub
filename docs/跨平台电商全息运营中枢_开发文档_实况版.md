## 1. 概述

```text
输入：淘宝/京东评价 xlsx（文本 + 买家秀图片 URL）
  ↓ M1 接入 + DQE 降噪 → M2 图片打标 → M3 分类 → M4 聚类/定价
  ↓ M5 优先级 + 提案 → M6 工具注册表 → M7 网关执行 → M8 可观测
  ↓ M9 复盘（DID）→ M10 交互 → M11 同款对齐
```

**技术栈（实际依赖）**：Python 3.13.9 / PostgreSQL / Redis 7.4 Stream /
FastAPI 0.162 / SQLAlchemy 2.0 / Alembic / pydantic 2.14 / PyJWT 2.15 / bcrypt 5.0 /
scikit-learn / openpyxl / **本地 Ollama**（`qwen2.5:7b` + `qwen2.5vl:3b`）

**明确不用**：LangChain 的 Chain/AgentExecutor、LLM Judge、向量库

## 3. 模块详细设计

### 3.1 M1 接入 + DQE

| 项 | 实现 |
| --- | --- |
| 读取 / 映射 / 归一化 / PII | `ingress/{reader,mapping,normalize,pii}.py` |
| DQE 规则轨 / ML 轨 / 融合 | `dqe/{rules,ml,fusion}.py` → `keep / drop / review` |
| 近似去重 | `dqe/simhash.py` |
| **实测** | 6950 → **4064 keep**（drop 2881 / review 5）；**降噪 42.1% / 41.0%** |

> ⚠️ `normalize` 里**标点不做压缩**（压了会让 DQE 规则 R003 误判 ✅）

### 3.2 M2 多模态

```text
sandbox → phash（去重 378 张）→ vision（本地 qwen2.5vl:3b）→ text_hint
   ↓
**合规**：`vision.py` **硬编码只连本地** ✅；`cloud_guard` 对图片**直接抛异常** ✅
**注意**：图片**从来没进过业务库**（只存打标结果）→ 旧版"阅后即焚"不准确 ✅
```

### 3.3 M3 分类

```text
输出是**行格式**（不是 JSON）：
   R1|quality,size|3|穿一次就起球
   id  问题类型   严重度 回显（校验串行）
   ↓ 为什么：实测 7B 输出 JSON 约 9% 缺字段/截断 → 整批报废
   ↓        行格式"必要字段在前、校验字段在后" → **漏回显也能用** ✅
失败：batch → 逐条救 → **关键词兜底**（`keywords.py`）；实测兜底 0 条 ✅
```

### 3.4 M4 聚类 / 定价 / M5 提案

| 模块 | 实现 |
| --- | --- |
| 聚类 | `analysis/cluster.py`（TF-IDF + 余弦）→ **22 簇** |
| 定价背离 | `analysis/price.py` → `anomaly.evidence{prices, review_rates, devs, title}` |
| 优先级 | `analysis/priority.py` → `priority_score` / `priority_tier` |
| **提案** | `action/proposer.py`：**args 由代码构造** ✅；`TOOL_BY_TOPIC` 选工具；`experience` 只**升**风险等级 ✅；`only_cluster` 支持只处理一个簇 ✅ |

### 3.5 M6 工具注册表

```python
ToolSpec(name, version, description, params_model,   # extra=forbid
         risk_level, required_role, evidence_types,
         handler, verify, compensate, outcome_metrics, timeout_s,
         idempotent)                                 # **只读工具必须 False** ✅
```

**工具清单**：写 = `catalog.query_price` / `listing.restore_desc` / `listing.update_desc` /
`product.update_price` / `review.draft_reply`；读 = `query_cluster` / `query_reviews` /
`query_history` / `query_product` / `query_outcome`

### 3.6 M7 执行（**网关顺序不能换**）

```text
① 参数校验（extra=forbid）→ ② 依据校验（类别/存在/指向）→
③ 幂等查询（**仅 idempotent=True** ✅）→ ④ 频控 →
⑤ 分级：L3 → PENDING_HITL；L2 → PENDING_APPROVAL（**都不执行**）→
⑥ 幂等占位 → 执行（重试）→ **回查 verify** → 失败补偿 → 审计
```

**队列**：

```text
kind = "full"                 → 全链 9 阶段（710 秒）
kind = "handle:<簇id前8位>"    → agent 任务（3~10 秒）
   ↑ `pipeline_run` 有 UNIQUE(kind) WHERE 活跃 → 同 kind 只能一条
     → 带簇 id：同簇幂等 ✅ 不同簇并行 ✅ 不用迁移 ✅
机制：PEL 认领 + 心跳 + 死信 + 重试上限
```

### 3.7 M8~M11

| 模块 | 入口 | 说明 |
| --- | --- | --- |
| M8 | `hub health/status/trace/eval` | trace_span 记耗时/token/cost |
| **M9** | `hub retro` | DID + bootstrap 区间；`reason_code` |
| M10 | `hub today` | 要我做 / 知会 |
| M11 | `analysis/align.py` | 跨平台同款 → `spu_align` |

**M9 的真实决定**：`refund_rate` **只展示、不参与判定** —— 实测 40 个 observation，
Δ差评率 与 Δ退款率 **同向仅 21/40 = 52.5%**（≈随机）→ 硬写进判定 = 用随机数判业务效果
（`16_阶段3.4_复盘指标扩展.md`）

### 3.8 agent（**形态③**）

```text
handle()：
  ① query_cluster  ┐
  ② query_reviews  ├ 参数**全部由代码给** ✅
  ③ query_history  ┘
  ④ llm.judge      ← **模型只出现一次**：{tool, evidence_ids, recommendation, confidence, why_not_rule}
  ⑤ 校验：工具在允许集合？引用编号真实存在（E-VERIFY）？与规则一致？（E-RULE）
  ⑥ 可选 Critic（第二模型核对，WRONG **只标记不拦**）
  ⑦ 可选 reflect（证据不足 → 补 query_product → 再判，**有界**）
```

**为什么这么限**（`14_Agent规划能力实测.md`）：收尾率 **0%**（6/6 用满 5 步）·
参数幻觉 **6/6**（UUID 抄错一位）· 无规则时 **22/22 选同一个工具**

**守护 `guard.py`**：取证步 ≤3 / 超时 300s / 并发 2 / token 20000 / Critic 连续 2 次转人工

### 3.9 阶段 3.6~3.9 + 4/5 的新模块

| 模块 | 关键设计 |
| --- | --- |
| `brief.py` | **每个数字必须在输入里找到** ✅；丢 >1 条重写一次；再不行只输出指标表 |
| `notify.py` | **先落库再派发**；幂等靠 DB `uq_notification_idem`；10 分钟合并；重试 3 次；**没配 webhook 标 SKIPPED** |
| `knowledge.py` | DRAFT → 人审 → PUBLISHED → **只追加不覆盖**；hash 带 version |
| `report.py` | xlsx 3 种；**导出前 PII 复查**；1 万行上限 |
| `rag/case_rag.py` | TF-IDF + topic 过滤 + Top-3；`0.6×相似 + 0.4×|effect|`；**伪造 case_id 只丢那条** |
| `mcp_server.py` | 6 个工具，**全部走 gateway.invoke** ✅ |
| `audit.py` | **业务层写**（CLI/API 都覆盖）；fail-open |
| `core/auth.py` | JWT 3 小时 + **服务端登出**（Redis 黑名单，TTL=剩余有效期） |

### 5.4 写（15）

| 路径 | 角色 | 关键行为 |
| --- | --- | --- |
| `POST /runs` | operator | **202**；重复 **409** + 已有 id；Redis 断 **503** |

```text

409 {code: ALREADY_RUNNING|ALREADY_PUBLISHED|NOT_DONE}
```

### 8.2 反复踩的坑（已写进规范）

```text
**测试自己打印的文本会匹配 FAIL_PAT** ✅ ✗
   · ❌ 当测试数据（check_normalize）
   · "失败 7 次"（check_brief）
   · 断言文案写 "最终 FAILED"（check_notify）
   ↓ FAIL_PAT = r"\[FAIL\]|有失败用例|\bFAILED\b|失败 [1-9]\d*\b"
   ↓ 明明全过却判失败 ✅
**规矩**：测试**文案**避开 FAIL/失败/❌；只有真失败才输出 [FAIL]
```
