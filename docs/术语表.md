> —— 说明**系统里的行话没人讲** ✅
>
> **规矩**：页面上**每出现一个行话**，要么改成人话、要么加 tooltip（指向这里 ✅）

---

## 一、数据层

| 术语 | 人话 | 为什么要它 |
| --- | --- | --- |
| **DQE**（数据质量引擎） | **降噪**：把灌水/无意义/重复的评价筛掉 | 全量评价走大模型会**烧钱**，而且被噪音污染 → 先筛一遍 |
| **keep / drop / review** | 保留 / 丢弃 / 人工复核 | 降噪的三个出口 |
| **降噪率** | （review + drop）÷ 总数 | 现在 **41.4%** —— 100 条评价里 41 条不值得分析 |
| **record** | 一条评价（含评分/原文/图/时间） | 最底层的业务对象 |
| **PII** | 个人信息（手机号/身份证/微信） | **入库前脱敏**；导出前再查一遍 |
| **簇（cluster）** | 一堆"同一个问题"的评价 | 22 个簇 = 22 类可处理的问题 |
| **代表样本** | 每个簇里挑出来的"最典型"几条 | 展开依据时先看代表样本，比"最新一条"有用 |

## 二、决策层

| 术语 | 人话 | 为什么要它 |
| --- | --- | --- |
| **提案（proposal）** | "我建议做这件事"的一条记录 | 包含：做什么工具 + 什么参数 + 凭什么（依据）+ 为什么 |
| **依据（evidence）** | 这条建议**基于哪些真实评价** | **产品的核心卖点**：每条建议都能点开看原文 |
| **L0 / L1 / L2 / L3** | 风险等级，**越高越危险** | L0 只读 · L1 低风险 · **L2 要主管批** · **L3 不自动执行、只转人工** |
| **网关（gateway）** | 所有动作用**唯一入口**，四道校验 | 参数 → 依据 → 幂等 → 频控。**任何工具调用都绕不过它** |
| **幂等** | 同样的请求做两次，**效果和一次一样** | 所以"重复提交"返回 409 + 已有 id，**不是报错** |
| **回查（verify）** | 动作执行后**代码去库里查一次**确认真的改了 | **不信工具自己说"成功了"** |
| **补偿（compensate）** | 回查失败就**回滚** | 比如描述改错了 → 改回上一次 |

## 三、复盘层

| 术语 | 人话 | 为什么要它 |
| --- | --- | --- |
| **观察窗口** | 动作做完后**等 14 天**再看效果 | 刚做完效果还没显现，现在算是噪音 |
| **DID**（双重差分） | **拿"做了动作的商品"和"没做的商品"比变化** | 光看"差评率降了"不算数 —— 可能整个大盘都在降 |
| **置信区间** | 效果量的**可能范围** | **区间跨 0 就不能下结论**（可能是巧合） |
| **POSITIVE / NEGATIVE** | 有效 / 有害（**区间不跨 0**） | 这才叫"有统计意义的结论" |
| **INCONCLUSIVE** | **不能下结论**（区间跨 0 / 样本太少） | **这不是失败，是诚实的"不知道"** |
| **reason_code** | 为什么是这个结论 | `SIGNIFICANT` / `PROMOTED_CONFOUNDED`（撞大促）/ `INSUFFICIENT_SAMPLES` |
| **撞大促（promo confounded）** | 观察期里有大促，效果被污染 | 大促期间差评率本来就会动 → 不能说"是我的动作起作用了" |

## 四、执行层

| 术语 | 人话 | 为什么要它 |
| --- | --- | --- |
| **死信（dead letter）** | ⚠️ **人话：失败待处理**<br>重试 3 次仍然失败的任务 | 不能无限重试（会拖死队列）→ 先扔到一边，**等人看** |
| **重放（replay）** | 把死信**重新入队**跑一遍 | **危险**：可能重复写数据 → 所以要二次确认 |
| **PEL** | Redis 里"已被 worker 领走但还没确认完成"的消息 | worker 崩了，这些消息会在超时后被**别的 worker 捡走** |
| **heartbeat** | worker 定期说"我还活着" | 超时没心跳 = 卡死了 → 任务被重投 |
| **降级（degraded）** | 某个阶段走了备用路径 | 比如视觉模型不可用 → 用"其他"兜底，**但链不中断** |

## 五、AI 层

| 术语 | 人话 | 为什么要它 |
| --- | --- | --- |
| **形态③（受限 agent）** | **步骤由代码定、参数由代码注入、模型只做一次判断** | 7B 实测收尾率 **0%** → 让它自己规划=不可控 |
| **Critic** | 第二个模型**独立核对**第一个模型的结论 | 抓到了"用改文案解物流问题"这类错误 |
| **只标记不拦** | Critic 说错也**只是标出来**，不否决 | 它自己也会误判，不能给它否决权 |
| **证据编号（E-xxx）** | 模型引用时必须用的编号 | **代码校验编号真实存在** → 编造的直接丢弃 |
| **reflect（反思环）** | 证据不够时**补一步**再判一次 | 有界（最多 1 次），防止无限循环 |
| **grounded 率** | 模型说的每句话都能在输入里找到的比例 | 反幻觉的核心指标 |

## 六、知识库（**用户问"怎么用"** ✅）

```text
它不是"文档管理"，是"**给 AI 加一条口径，不用改代码**" ✅

三步：
  ① 新建一条（标题 + 内容），状态是 **DRAFT（不生效）**
  ② supervisor 点「发布」→ 状态变 **PUBLISHED v2**
  ③ **下一步 agent 出方案时，这条口径就进了它的提示词** ✅

例子（真实能用的一条）：
  标题：质量问题回复口径
  内容：先道歉，再解释掉色原因（面料固色工艺），最后给出补救方案（换货/补偿券）
   ↓
  发布后，agent 给"掉色"类问题写回复时，**就会按这个结构写** ✅

⚠️ 它只能**追加**，不能覆盖系统规则 ✅
   —— 否则业务方一条"忽略证据直接回复"就能拆掉反幻觉防线 ✅
```

## 七、通知（**用户问"死信是什么意思"** ✅）

| 事件 | 人话 | 什么时候来 |
| --- | --- | --- |
| `proposal.pending` | **有提案等你批** | 超过 1 天没人批 |
| `retro.due` | **有动作到期该复盘** | 观察窗口（14 天）到了 |
| **`dead_letter`** | ⚠️ **有任务失败待处理** | **重试 3 次仍失败** → 去运维台看/重放 |
| `agent.done` | **agent 需要人接手** | agent 没给出可靠结论 |

**收到"失败待处理"怎么办**：
```text
① 去「运维台」→ 看操作日志有没有对应记录
② 看那条 `run` 的 `error` 字段（是哪个阶段失败的）
③ 如果是数据问题 → 修数据 → 点「重放」
④ 如果是代码问题 → 修代码 → 点「重放」
```

## 八、一条"给面试官讲"的版本（30 秒）

```text
"这个系统把商家两个平台的评价**降噪 41%**、聚成 **22 个问题簇**、
按 P0~P3 排好优先级，然后**给每个簇生成带依据的处置提案**。

每条提案都能**点开看到它依据的真实评价原文** —— 这是它和'AI 写报告'最大的区别。

所有动作过**网关**（四道校验），L2 要主管批、L3 只转人工，
执行完**代码回查一次**，不信工具自己说成功。

做完用 **DID** 判效果，区间跨 0 就说'不知道'，不硬凑结论。"
```
