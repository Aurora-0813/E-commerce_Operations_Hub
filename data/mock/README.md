# Mock 数据说明（data/mock/）

本目录是**仿真森马店铺（男女装混合）的电商导出数据**，严格模拟真实商家后台"点导出 → 直接导入"的文件形态。

## 文件清单

| 文件 | 模拟对象 | 用途 |
| --- | --- | --- |
| taobao_review_202610.xlsx | 淘宝千牛·评价管理导出 | 适配器 + DQE + 归因（评价等级=好/中/差） |
| jd_review_202610.xlsx | 京东商智/京麦·评价导出 | 适配器 + 跨平台对齐（星级 1-5 + 标签 + 追评） |
| product_202610.xlsx | 商品主数据导出 | 同款对齐（森马同款在两边，标题相似） |
| sales_daily_202610.xlsx | 生意参谋/商智 销售导出 | M11 数据面（价格背离 / 销量预测） |
| gold_labels.csv | 人工标注集（内部工作文件） | 评测（字段 F1 / 分类 F1 / 水军 F1） |

> 生成方式：`python backend/scripts/generate_mock.py`（固定 seed=42，可复现）。

## 真实格式要点（对齐商家后台）

1. **Excel(.xlsx)，第一行就是表头**，无"说明行"；
2. **淘宝**：评价等级 = `好评/中评/差评`；**京东**：评价星级 = `1-5` + 评价标签 + 追评；
3. **商品标题带品牌**：`森马 夏季碎花连衣裙收腰显瘦中长款`；
4. **金额带货币符号**：`￥199.00`（测 Decimal 清洗）；
5. **脱敏昵称**：淘宝 `t***1`、京东 `j***buyer01`（PII）。

## 故意埋的脏数据（真实会出现的情况）

1. **合计行**：京东评价导出末尾有"合计"行 → 测剔除；
2. **中间空行**：数据中间偶发空行 → 测跳过；
3. **坏行**：约 1% 行"评价内容"为空（必填缺失）→ 测坏行隔离；
4. **千分位/货币符号金额** → 测 Decimal 清洗；
5. **评分两种写法**：好/中/差 vs 1-5 星 → 测评分映射；
6. **PII 脱敏昵称** → 测 PII 丢弃；
7. **水军/灌水**：`此用户没有填写评价`、`好评`、`111111`、重复的`质量不错`、`加微信xxx`、`13800138000` → 测 DQE 规则轨；
8. **带图差评**：破洞、色差（图片 URL）→ 测多模态沙箱；
9. **追评**：京东约 10% 有追评 → 测追评合并；
10. **跨平台同款**：森马同款在淘宝/京东都上架，且个别商品京东价比淘宝高 → 测同款对齐 + 价格背离。

## 拿到真实导出数据后，照这份清单对齐（防止遗忘）

> 拿到真实淘宝/京东导出文件时，逐项核对，把差异更新回 `backend/config/mappings/`（或 `generate_mock.py`）。

### 第 1 步：核对列名

1. 打开真实文件，把**第一行表头**完整复制出来；
2. 对照 mock 的表头（见本 README 或 `generate_mock.py` 里的 `header`），逐列找差异：
   - 真实文件**多了哪些列**（如"是否匿名""买家秀视频""订单状态"）→ 决定要不要、映射到哪个目标字段；
   - 真实文件**少了哪些列** → mock 里有的、真实没有，说明 mock 要删；
   - **同名不同字**（如"追加评价"vs"追评"）→ 记下来，写进字段映射的候选列表。
3. 把结果更新到 `backend/config/mappings/{taobao,jd}.yaml`（开发到 03 时会建）。

### 第 2 步：核对编码

1. xlsx 文件：无编码问题（内部是 XML），跳过；
2. 若商家导出的是 **csv**：
   - 用记事本打开，看中文是否乱码 → 乱码就是 GBK；
   - 或者命令行 `python -c "print(open('xx.csv','rb').read(200))"` 看前 200 字节；
3. 确认是 GBK → 适配器 03 的编码探测逻辑（先 UTF-8 后 GBK + 中文占比校验）已经覆盖，无需改代码，只需用真实文件测一次。

### 第 3 步：核对多 sheet

1. 打开真实文件，数有几个 sheet、各叫什么名；
2. 常见情况：
   - 只有 1 个"数据"sheet → 最简；
   - 有"数据说明"/"指标口径"sheet → 适配器要能**跳过或单独存**；
   - 多个数据 sheet（如"好评""差评"分开）→ 适配器要循环处理。
3. 把 sheet 名字记进字段映射配置。

### 第 4 步：核对脏数据

1. 看真实文件里实际有哪些脏情况：空行、合计行、合并单元格、千分位、脱敏昵称、空单元格；
2. 对照本 README 的 10 类脏数据清单，**补上真实出现但 mock 没有的**（如合并单元格）；
3. 更新 `generate_mock.py` 或字段映射。

### 第 5 步：回填并复测

1. 用真实文件跑一次 `make p0`（适配器），看能不能正确解析；
2. 失败 → 按报错定位到"列名/编码/sheet"哪一类，修对应配置；
3. 修好后把真实表头存档（截图或贴进 README），以后有新文件直接对照。
